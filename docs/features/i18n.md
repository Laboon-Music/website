# Languages (French and English)

The whole website exists in **French** (default) and **English**.

| Language | URL          | Example                 |
| -------- | ------------ | ----------------------- |
| French   | no prefix    | `/`, `/contact`, `/cgu` |
| English  | `/en` prefix | `/en`, `/en/contact`    |

`/fr/…` redirects (308) to the address without a prefix: one address per page.
The visitor is **never redirected by browser language or country**: the footer
link ("English" / "Français") is the way, and it keeps the current page.

## How it works

- **Routing**: every page lives under `app/[lang]/`; `proxy.ts` rewrites unprefixed
  URLs to `/fr/…`. Unknown URLs fall into `app/[lang]/[...slug]` and show the 404 in
  the right language. `lib/i18n.ts` has the helpers (`localePath`, `splitLocale`, `fmt`…).
- **Texts**: `content/fr/*` and `content/en/*` (`home`, `faq`, `site`, `ui`). The English
  files are **typed on the French ones**: a missing key does not compile.
  `content/content.test.ts` also checks the same `{placeholders}` and links, and that
  nothing is empty. `getContent(locale)` on the server, `useUi()` in client components.
- **Links**: `LocalizedLink` (used by `TextLink`, `ButtonLink`, header, footer…) turns
  `/contact` into `/en/contact` on English pages. Write links in code and texts
  **without** a prefix.
- **SEO**: `<html lang>`, a page title and description per language, `hreflang`
  alternates + canonical on every indexable page (`lib/page-metadata.ts`), sitemap with both
  languages, JSON-LD and share image per language. Embeds, account links and the
  confirmation page are `noindex` in both languages.
- **Forms**: the page language is sent as `locale`; the API routes answer in it
  (`lib/request-locale.ts`). The signup e-mail uses the English Brevo template and the
  contact `LANGUAGE` attribute is set (see below).
- **Legal documents**: already in both languages (`components/legal/content/{fr,en}`),
  same slugs (`/en/cgu`, `/en/mentions-legales`…).

## Pages opened from outside the site

`?lang=en` selects the English page for: `/faq/embed`, `/contact/embed`, `/legal/<slug>`
(mobile app WebViews) and `/reset-password`, `/confirm-email` (e-mailed by the Laboon
API: it should add `&lang=en` to the link, or use `/en/…`, for English accounts).
Without it, French is served.

## Adding or changing a text

1. Edit `content/fr/…` **and** `content/en/…` (same key). Placeholders look like `{name}`.
2. Run `npm run check`: the parity test fails if the two languages differ.

## Adding a language

Add it to `LOCALES` in `lib/i18n.ts`, create `content/<lang>/` (`home`, `faq`, `site`, `ui`) and
`components/legal/content/<lang>/`, register them in `content/index.ts`,
`components/i18n/LocaleProvider.tsx` and the legal registry, add its e-mails
(`emails/templates.ts`) and Brevo template. The footer switch lists the other languages.

## Brevo

- Confirmation e-mail template per language: `BREVO_DOI_TEMPLATE_ID` (French) and
  `BREVO_DOI_TEMPLATE_ID_EN` (English, optional: falls back to the French template).
- Create the contact attribute **`LANGUAGE`** (text) so the language of each subscriber is kept.
- The confirmation page after the double opt-in is `/inscription-confirmee` or
  `/en/inscription-confirmee` according to the signup language.
